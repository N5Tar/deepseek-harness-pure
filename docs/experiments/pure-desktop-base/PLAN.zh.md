# DSH 纯净桌面底座实施计划 V0.2

[English](PLAN.md) | 中文

## 摘要

本计划用于从 DSH 源码中整理一个以 Cordis 为核心、与 AI（人工智能）业务无关的桌面基础运行环境。目标是在无账号、无模型配置、无 API Key、无 Session、无 agent（智能体）服务的条件下，启动桌面界面、加载业务插件、保存设置、正常退出，并在插件故障后恢复。

本文是规划参考，不是现有产品使用指南或实验结果。日期为 2026-11-04；方案范围已确认，实现进展见[执行进度](STATUS.zh.md)。源码调查只构成静态依据，不构成 Web、Desktop 或发行验证通过的证据。后续实现者负责执行各阶段验证并记录结果。

## 目标与范围

本计划替代 V0.1 的换壳实验目标：业务服务裁剪是必做项，允许必要的 Electron 宿主解耦，默认恢复目标是纯净 Shell，而不是官方聊天界面。不能用隐藏界面、缺依赖后的被动失活或模拟业务服务代替裁剪。

### 必须保留

| 能力 | 第一版要求 |
|---|---|
| Cordis 与 Loader | 服务注入、事件、配置组合、生命周期及资源释放 |
| Desktop 宿主 | 窗口、单实例、Host 启停、退出、重启及独立数据目录 |
| Client 基础设施 | 模块加载、React Renderer、Slots 与默认 Root |
| 安全通信 | 必要的 Host/Client 通信、认证和访问限制 |
| 基础设置 | 语言、主题与产品设置持久化 |
| 插件管理 | 可靠的本地安装、启停与错误报告路径，不要求在线市场 |
| 诊断与恢复 | 日志及不依赖业务 Root 正常渲染的恢复入口 |
| 开发与发行 | 构建、调试、受控重载及当前 macOS 的独立开发产物 |

### 默认排除

- Agent Loop、Session、会话持久化和对话控制器。
- 模型提供者、账户登录、API Key 引导和官方 AI 欢迎流程。
- 工具执行、终端、工作区文件操作、浏览器及计算机自动化。
- Team、Workflow、Goal、Schedule 和面向 agent 的技能与提示词。
- 官方聊天、侧边栏、对话设置和其他业务 UI。
- 官方产品分析上报、在线插件市场和默认外部业务连接。

基础认证需要的凭证能力不属于可直接删除的账户业务。排除要求先落实到运行组合，再落实到发行依赖；仓库暂时保留业务源码，不代表基础产物必须携带这些业务包。

### 非目标

- 正式主题商城、完整产品功能或重新接入 AI 能力。
- 通用跨平台自动更新系统和在线插件市场。
- 任意不可信插件的安全沙箱；可撤销生命周期不等于安全隔离。
- 重写 Cordis、React 或 Electron，以及为减包而进行全仓重构。
- 正式签名、公证、线上发布或未经实测的平台支持承诺。

第一版以当前 macOS 为验收平台；Windows/Linux 未测试时标记为 UNKNOWN。后续产品可通过独立业务组合接入 AI，但第一版不为尚不存在的消费者预建接口。

<a id="target-structure"></a>

## 目标结构

基础组合采用白名单，不继承完整 Web bundle 后长期维护禁用清单。沿用受支持的 Profile 启动机制；最终包名和目录在阶段 0 按仓库规范确定。

| 组合 | 职责 | 不应依赖 |
|---|---|---|
| 桌面基础组合 | Loader、通信认证、模块加载、Renderer、基础设置、诊断恢复 | Session、agent、模型、账户业务 |
| 默认 Shell 组合 | 最小 Root、窗口适配、设置入口、插件状态与错误入口 | 官方聊天布局与会话 hooks |
| 产品组合 | 产品页面、Host 服务及按需选择的业务能力 | 未声明的默认 AI 服务 |

通用模块能独立复用则直接复用；混合职责的模块只做必要拆分。不复制整套官方 UI，不造假业务服务，不吞掉依赖错误。退出与更新不应硬编码 agent 任务；优先使用现有通用生命周期机制，新增扩展点必须有真实消费者。

<a id="implementation-phases"></a>

## 实施阶段

阶段按顺序推进，每阶段保存最小变更、验证记录和已知限制。失败时记录具体阻断及可选方案，不静默绕过，也不以可见页面代替完整验收。

### 阶段 0：隔离与基线

- 创建独立实施分支；记录源码版本、操作系统、工具链和工作区状态，不在主分支提交改造。
- 显式隔离 Harness home、Electron userData、调试端口、日志和构建输出；检查单实例锁。
- 核对开发启动器的下载、运行时准备与构建行为，不关闭用户现有 DSH 进程。
- 建立无登录、无模型调用的原版 Desktop 启动基线，区分环境问题和后续裁剪问题。
- 产出环境说明、可复核启动步骤和初始依赖表；通过条件是实验实例与现有安装互不干扰。

### 阶段 1：白名单基础组合

- 从空组合建立独立基础 bundle/profile，按真实依赖选择启动、配置、模块、通信认证、Renderer 和必要设置。
- 创建最小 Root，展示底座名称、连接状态、版本和静态示例区域，不使用 Session 数据或会话 hooks。
- 为每个保留模块记录服务、必需注入、Host/Client 职责、直接及间接依赖和保留理由。
- 产出基础组合、Root、依赖闭包及无模型启动测试；可先用浏览器诊断，但不算桌面完成。
- 通过条件是无 Agent/Session/模型业务条目、无未解释的 pending/failed，且 Host 就绪、Client 激活、Root 挂载及重启可复核。

### 阶段 2：Electron 业务解耦

- 取消 AI 欢迎窗口以及账户、模型、API Key 状态作为桌面启动前提。
- 桌面就绪仅依赖必要 Host、通信、Client 基础组合和可渲染 Root。
- 移除退出与更新对 agents/jobs 的直接依赖；第一版关闭未适配的官方在线更新路径，不留下半可用更新器。
- 默认初始化和故障恢复都使用纯净组合；保留用户数据与可审计的配置备份。
- 产出启动、退出、重启和恢复路径；通过条件是全新目录无账号/key 可进入主窗口，无会话服务仍可正常完成生命周期。

### 阶段 3：通用 Client 与 Shell

- 提供仅含必要接口的 Remote assembly，让业务组合自行选择业务代理。
- 明确主题状态、设置持久化和 DOM 呈现职责，提供最小语言/主题设置，不保留模型或会话设置。
- 验证拖拽区域、macOS 交通灯避让、原生菜单、最小窗口尺寸、焦点与主题同步。
- 提供插件错误定位和不依赖业务 Root 的原生恢复；先保证受控重启可靠，不承诺任意 Root 无缝热替换。
- 产出默认 Shell、设置界面和错误恢复测试；通过条件是无官方 layout/sidebar/conversation 依赖、设置跨重启保存、窗口交互与恢复可用。

### 阶段 4：业务插件样例

- 样例 A 注册纯 Client 页面或面板，使用 Slots 和基础主题，验证启用、停用与贡献撤销。
- 样例 B 提供最小 Host 服务，通过受控 Remote 调用并保存一个非敏感设置。
- 验证安装、启停、卸载、重启、依赖缺失、插件异常和资源释放，检查重复监听与挂载。
- 产出两个样例、开发加载说明和真实组合测试，不建设在线市场。
- 通过条件是样例不引用会话业务或完整 Web 组合，停用后服务、Slot 和效果按预期撤销。

### 阶段 5：构建与发行依赖

- 检查源码存在、包安装、运行激活、浏览器下发和发行携带五个维度，不混淆禁用与减包。
- 排除不必要的 AI、终端、自动化和大型业务运行时，核对静态 Web 平台内容。
- 设置独立应用标识与数据路径，避免注册或抢占官方应用协议，检查第三方许可证。
- 生成当前 macOS 的开发产物，测量大小与启动资源，记录签名、公证和更新的未完成项。
- 通过条件是产物脱离源码和开发服务器仍能启动，不借用现有安装的配置或运行时，且没有意外重新引入完整业务组合。

### 阶段 6：最终验收

- 执行下方矩阵；每项记录 PASS、FAIL 或 UNKNOWN，以及源码版本、平台和证据路径。
- 汇总保留/移除依赖、已知限制、恢复步骤、开发运行方式和发行验证结果。
- 完成条件是新用户无需理解模型、账号或会话，就能启动应用、修改设置、运行样例、退出重开并从插件故障恢复。

<a id="testing-and-deliverables"></a>

## 测试与交付

测试必须覆盖真实入口。组合测试使用真实 Loader；UI 测试无需模型；Desktop 生命周期和发行产物分别验证。按实际改动运行聚焦单元测试、组合测试、浏览器测试和构建校验，不能用源码测试代替发行验证，也不默认重复全仓测试。

建议按基础组合、Root、Desktop 解耦、生命周期恢复、Client 拆分、样例、发行收敛分开提交。并行工作必须声明不重叠的写入范围；Host 与 Client 依赖有顺序时先明确接口，再实现消费者。最终由主实施者检查完整差异并运行集成检查。

最终交付包括基础组合与 Shell、必要宿主改造、两个样例、开发/构建/恢复说明、依赖矩阵、测试结果和当前平台开发产物。原始日志、截图和运行证据放在被忽略的产物目录；只纳入脱敏摘要，不提交令牌、Cookie、密钥、个人配置或真实聊天数据。

实际命令、包名和完整最小模块集合由各阶段实施者验证后写入运行说明。本文不提供未经执行的启动命令，不宣称存在现成的 shell-minimal 产品。

<a id="risks-and-open-choices"></a>

## 风险与待定事项

| 风险或选择 | 处理原则 |
|---|---|
| 通用模块混有业务依赖 | 追踪消费者后局部拆分，不用假服务 |
| Root 失败导致白屏 | 原生恢复独立于业务 UI，恢复到纯净组合 |
| 裁剪凭证破坏安全 | 保留通信认证，仅移除不需要的业务消费者 |
| 上游新增功能渗入 | 白名单组合与回归测试，不维护长期黑名单 |
| 开发通过而打包缺文件 | 独立检查发行依赖和脱离源码启动 |
| 过早删除源码 | 先稳定组合与产物，再考虑源码清理 |
| 包体和性能收益不确定 | 测量后报告，不预先承诺比例 |
| 产品名称、标识与发行渠道 | 打包前确定；在此之前仅使用隔离开发身份 |
| 未来插件信任模型 | 第一版只运行受信任插件，不宣称权限隔离 |
| 自动更新和 AI 接入 | 第一版之外；不得保留失效的默认路径 |
